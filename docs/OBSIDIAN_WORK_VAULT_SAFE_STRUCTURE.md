# Obsidian Work Vault Safe Structure

> v1.11 | 公司入职工作 Vault 安全边界

## 核心理念

两个独立的 Obsidian Vault：

| Vault | 路径 | 用途 | 安全规则 |
|:---|:---|:---|:---|
| 个人学习 | `D:\Obsidian\Unity学习知识库` | ET6源码学习、Unity UI架构、面试知识库、think-tank | 可保留完整细节 |
| 工作 Vault | `D:\Obsidian\WorkVault_Private` | 脱敏经验、SOP、Checklist、日报模板 | **只存脱敏内容** |

## 工作 Vault 目录结构

```text
WorkVault_Private/
├── 00_安全边界/          ← 安全规则速查、禁止事项清单
├── 01_每日WorkCard/       ← 每天一张轻量卡片
├── 02_问题复盘_脱敏/      ← Bug排查经验（抽象后）
├── 03_提问模板/           ← 向导师/同事提问的话术模板
├── 04_日报周报/           ← 汇报草稿和最终版
├── 05_Checklist/          ← 可累积的检查清单
├── 06_SOP/                ← 标准操作流程
└── 99_禁止事项/           ← 公司安全规范、泄密案例警示
```

## 各目录说明

### 00_安全边界/

**放什么**:
- 个人工具使用边界的确认记录
- 公司安全规范的抽象总结
- Company Policy Gate 的当前状态（UNKNOWN/ALLOWED_NOTE/DENIED）
- 禁止事项速查卡

**不放什么**:
- 公司安全文档原文
- 公司内网地址
- 具体工具名称（如公司内部 IM 系统名）

### 01_每日WorkCard/

**放什么**:
- 每天用 `templates/office_onboarding/work_card.md` 生成的一张卡片
- 命名规则: `YYYY-MM-DD_WorkCard.md`

**不放什么**:
- 公司源码片段
- 内部路径
- 内部类名/方法名

### 02_问题复盘_脱敏/

**放什么**:
- 抽象问题类型: "网络同步问题排查流程"、"UI 生命周期陷阱总结"
- 通用排查流程
- 经验教训（脱敏后）

**不放什么**:
- 具体 Bug 单内容
- 公司源码
- 内部文档原文

**示例（可以写）**:
> "排查网络同步问题时，先确认客户端是否发出请求 → 服务端是否收到 → Handler 是否执行 → reply 是否返回 → 客户端是否收到回包。"

**示例（不能写）**:
> "C2Game_DNAUnlockHandler 在处理解锁请求时，PlayerNerveComponent 的 m_dicNerve[101] 为空导致空引用。"

### 03_提问模板/

**放什么**:
- generator_question.md 模板的精华版
- 实际用过的有效提问话术（脱敏）

**不放什么**:
- 导师或同事的回答内容（如涉及公司信息）
- 公司内部截图

### 04_日报周报/

**放什么**:
- 脱敏日报
- 脱敏周报
- "可发送版本"（经过脱敏，可直接发给导师）

**不放什么**:
- 未脱敏的草稿
- 包含具体类名/路径/协议的描述

### 05_Checklist/

**放什么**:
- 环境检查 checklist
- UI 修改 checklist
- 配置表修改 checklist
- Bug 排查 checklist
- 提测前 checklist
- 命名规范 checklist（通用版）

**不放什么**:
- 包含公司具体字段名的 checklist
- 公司代码审查清单原文

### 06_SOP/

**放什么**:
- 入职第一周 SOP
- 接需求 SOP
- Bug 排查 SOP
- 任务复盘 SOP

**不放什么**:
- 包含公司工具名称/流程的具体 SOP
- 公司内部 Wiki 的翻译版

### 99_禁止事项/

**必须写入（不可协商）**:

```text
❌ 禁止保存公司源码
❌ 禁止保存内部路径
❌ 禁止保存内部类名/方法名
❌ 禁止保存协议名/字段名
❌ 禁止保存配置表字段
❌ 禁止保存资源名/Prefab名
❌ 禁止保存服务器地址
❌ 禁止保存账号/Token/Key
❌ 禁止保存未公开玩法/活动/数值
❌ 禁止保存具体 Bug 单内容
❌ 禁止保存内部文档原文
❌ 禁止将工作 Vault 上传到 GitHub
❌ 禁止将工作 Vault 同步到外部云服务
```

## 写入前检查（Persistence Gate）

每次向工作 Vault 写入内容前，必须对照 `99_禁止事项/` 的清单逐一检查。

在 Obsidian 笔记末尾添加：

```markdown
## 敏感信息检查

- [ ] 不包含公司源码
- [ ] 不包含内部路径
- [ ] 不包含内部类名/方法名
- [ ] 不包含协议/配置字段
- [ ] 不包含资源名/Prefab名
- [ ] 不包含服务器地址/账号/Token/Key
- [ ] 不包含未公开玩法/活动/数值
- [ ] 不包含具体 Bug 单内容
```

## 常见问题

**Q: 我可以把公司项目的架构画出来存进去吗？**

A: 可以，但只能用抽象术语。写 "UI 层→ModelView 层→HotfixView 层" 可以，写 "DlgDNAMain.cs 在 Unity/Codes/HotfixView/Client/DlgDNA/DlgDNAMain/ 下" 不行。

**Q: 导师给我的代码片段可以存吗？**

A: 不行。代码片段包含类名和方法名，属于禁止保存的内容。你可以在理解后用抽象语言重新描述。

**Q: 工作 Vault 可以用 Git 吗？**

A: 可以，但只限本地。**绝对不要 push 到 GitHub 或其他远程仓库。**
