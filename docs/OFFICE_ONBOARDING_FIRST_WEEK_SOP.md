# Office Onboarding First Week SOP

> v1.11 | 入职热区网络后使用

## 总原则

```
安全合规 > 跑通环境 > 看懂项目 > 接住小任务 > 提升效率
```

---

## Day 1：确认规范 + 跑环境

### 目标

- 确认个人工具使用边界
- 确认阿瑞斯病毒2项目启动方式
- 记录环境配置流程
- **不急着用 Hermes 处理项目**

### 早上：确认工具使用边界

用 `templates/office_onboarding/mentor_question.md`，向导师确认：

| 问题 | 示例话术 |
|:---|:---|
| Unity 版本 | "项目用的是哪个 Unity 版本？" |
| IDE | "团队用 Rider 还是 VS？有推荐配置吗？" |
| 分支规范 | "项目是 main 开发还是 dev 开发？有分支命名规则吗？" |
| 配置表流程 | "配置表是 Excel 直接导出还是走工具链？" |
| AB / 热更 | "项目用 AssetBundle 还是 Addressable？HybridCLR 还是 ILRuntime？" |
| 日志查看 | "本地调试看 Console 还是有专门的日志工具？" |
| 个人笔记和工具 | "组里对个人笔记工具有限制吗？我可以用自己的笔记软件记录学习过程吗？" |

### 下午：跑环境

| 步骤 | 验证 |
|:---|:---|
| 拉代码 | 确认仓库地址、拉取分支 |
| Unity 打开 | 确认版本、等待编译、Console 0 error |
| 跑起来 | 确认服务端启动、客户端 Play、GM 面板可用 |
| 看懂启动链路 | 记录从入口到游戏主界面的关键步骤 |

### Hermes 可做

- 生成导师提问话术（mentor_question 模板）
- 记录脱敏 Work Card（work_card 模板）
- 生成环境问题清单
- 整理日报草稿（daily_report 模板）

### Hermes 禁止做

- ❌ 扫描公司项目目录
- ❌ 读取公司源码
- ❌ 调用 Codex
- ❌ 保存公司细节（路径/类名/协议/配置）

### 当日产出

- [ ] Work Card
- [ ] 工具边界确认记录
- [ ] 环境启动 checklist
- [ ] 日报草稿

## Day 2：理解项目启动链路

### 目标

- 知道阿瑞斯病毒2如何启动（客户端 + 服务端）
- 知道客户端入口大致流程
- 知道日志怎么查

### 学习路径

1. 看服务端启动脚本（不保存路径）
2. 看客户端 Init/Start 入口（记录流程，不记录类名）
3. 手动加一次 Debug.Log，确认改动生效
4. 确认 HybridCLR 热更机制（BuildCodeDebug 流程）

### Hermes 可做

- 抽象记录启动步骤（流程图级别，不含类名）
- 整理不懂的问题清单
- 生成导师提问清单
- 整理日报

### 禁止

- ❌ 保存具体路径、类名、协议、内部文档原文

### 当日产出

- [ ] 个人理解的启动流程图（脱敏）
- [ ] 不懂的问题清单
- [ ] 日报

## Day 3：理解 UI / 配置 / 资源

### 目标

- 理解 UI 修改大致流程
- 理解配置表更新大致流程
- 理解资源/AB/热更大致流程

### 学习路径

1. 找一个简单 UI Prefab，理解层级结构
2. 找一张简单配置表，理解字段含义
3. 看一次 AB 打包流程（如果项目用 AB）

### Hermes 可做

- 做抽象流程图
- 做通用 checklist
- 做问题复盘（脱敏）

### 当日产出

- [ ] UI 修改流程 checklist
- [ ] 配置更新流程 checklist
- [ ] 日报

## Day 4：接第一个小任务

### 目标

- 用 office-lite 模式拆第一个真实小任务
- 明确影响面、验收标准、需要问谁

### 流程

1. 收到任务描述 → 用 `requirement_intake_lite.md` 模板记录
2. 识别歧义 → 用 `mentor_question.md` 向导师确认
3. 拆解影响面 → 客户端/服务端/配置/UI/测试
4. 写验收标准 → 做完后拿什么验证
5. 完成任务（手动编码） → Hermes 只辅助思考和验收
6. 复盘 → 用 `task_retrospective.md` 沉淀经验

### Hermes 可做

- 需求摘要、歧义点、影响面拆解
- 验收标准、风险提醒
- 汇报草稿
- **不调用 Codex 修改公司代码**

### 当日产出

- [ ] Requirement Intake Lite
- [ ] 确认过的问题清单
- [ ] 任务完成记录
- [ ] 脱敏复盘

## Day 5：第一周复盘

### 目标

- 复盘环境、规范、理解、任务、心态
- 提炼可复用 checklist
- 决定是否升级 Hermes 规则（如发现新断裂点）
- 准备下周计划

### 复盘维度

| 维度 | 自问 |
|:---|:---|
| 环境 | 开发环境全部跑通了吗？还有什么没配置？ |
| 规范 | 知道命名/目录/提交/代码审查规范了吗？ |
| 理解 | 能独立从代码中找到修改点了吗？ |
| 任务 | 接到小任务能独立拆解了吗？ |
| 协作 | 知道找谁问什么问题了吗？ |

### Hermes 可做

- 生成脱敏复盘
- 生成下周计划
- 判断是否需要升级 Hermes 规则（如发现可沉淀的经验）

### 当日产出

- [ ] 第一周脱敏复盘
- [ ] 可沉淀的 checklist
- [ ] 下周计划
- [ ] Company Policy Gate 状态更新（如有新信息）
