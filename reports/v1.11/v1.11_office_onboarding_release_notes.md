# v1.11-office-onboarding Release Notes

> 日期：2026-07-02 | 分支：`feature/v1.11-office-onboarding`

---

## 1. v1.11 的定位

v1.11 不是 v1.10 的功能升级。它是一个**安全层**——在 v1.10 SDD-Harness 管线骨架外面加了一个"公司入职安全壳"。

```
v1.10: 个人测试题工程 → full/quick/intake → 完整管线
v1.11: 公司入职场景 → Office Layer（安全壳）→ v1.10 管线（受控进入）
```

## 2. 为什么需要 Office Onboarding

v1.10 假设：
- 已知项目规范（ET6 命名铁律）
- 可写入项目代码（HotZoneTestC/DailyReward）
- GM 面板可用
- Codex/Claude Code 可无限制调用

入职阿瑞斯病毒2后，这四个假设全部不成立。v1.11 在能确认规范之前默认为 safe-note（最保守模式），逐步升级到 office-lite → full-harness。

## 3. 新增四种模式

| 模式 | 触发 | 允许 |
|:---|:---|:---|
| **safe-note** | 公司规范未知 | 脱敏笔记 + 模板生成 |
| **office-lite** | 允许个人笔记 | + 需求拆解/歧义识别/影响面分析（不接触源码） |
| **full-harness** | 公司允许 + 用户授权 | 完整 v1.10 管线（限授权范围） |
| **personal-lab** | 个人项目 | 完整 v1.10 管线（无安全限制） |

## 4. 新增五个 Gate

| Gate | 作用 |
|:---|:---|
| **Company Policy Gate** | 根 Gate — UNKNOWN→safe-note, DENIED→永久封禁 |
| **Sensitive Data Gate** | 每次输出前扫描 → 自动脱敏或阻断 |
| **Action Permission Gate** | 6 级动作权限 — L6(commit/push)永远禁止 |
| **Persistence Gate** | 阻止保存公司具体实现到文件/Obsidian/memory |
| **Mode Switch Gate** | 三线切换必须用户确认 |

## 8. 入职第一周使用方式

1. Day 1: safe-note — 确认规范 + 跑环境
2. Day 2-3: safe-note/office-lite — 理解项目
3. Day 4: office-lite — 接第一个小任务
4. Day 5: office-lite — 第一周复盘

详见 `docs/OFFICE_ONBOARDING_FIRST_WEEK_SOP.md`

## 9. 降级策略

```
公司规范未确认 → 强制 safe-note
导师禁止 → 永久 safe-note
输出含敏感信息 → 自动脱敏
请求越权操作 → BLOCKED
```

不可降级的底线：
- 绝不自动提交/推送代码
- 绝不绕过 Company Policy Gate
- 绝不在 DENIED 状态下接触公司代码

## 10. 不做的事情

- 不后台常驻
- 不接入公司 CI/CD
- 不自动扫描公司项目
- 不把公司内容发给 ChatGPT
- 不在公司电脑上创建定时任务

## 11. 后续建议

- 入职第一周按 SOP 执行 → 更新 onboarding metrics
- 确认公司规范后 → 升级 Company Policy Gate
- 接 3 个以上任务后 → 评估是否升级到 full-harness
- 发现新断裂点 → 走 experience injection 通道升级规则
